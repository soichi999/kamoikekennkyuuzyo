# 分析タスク — 町丁目単位のポアソン回帰で危険度係数を出す

Python 3 + ローカル実行。最終目的は **`real.js` に貼る係数を得ること**。

## 背景

カケコミ = 子どもが「助けて」と駆け込める場所の密度をスコア化するアプリ。

メールけいしちょうの不審者情報には **報告バイアス** がある。
実際、人口あたり件数は自治体間で最大9倍の開きがあり、これは治安差ではなく所轄警察署の投稿頻度差。

そこで、報告データを直接スコアにするのではなく、
**環境要因（駆け込み先の密度）から危険度を推定する式** を作る。

## 入力データ

| 中身 | ファイル | 備考 |
|---|---|---|
| 不審者情報 | `raw/CRIME RAW DATA.csv` | 住所テキストあり。丁目まで特定できる行のみ使う |
| 町丁目境界+人口 | `raw/東京都人口/`（e-Stat 小地域 Shapefile） | 属性に `JINKO`（人口総数）が入っているはず |
| 交番・駐在所 | `processed/交番場所.csv` | 警察庁。緯度経度あり |
| 学校 | （手元のCSV） | 緯度経度あり |
| コンビニ | OSM Overpass | 下記クエリで取得 |

Overpass クエリ（東京23区の東側を bbox で指定）:
```
[out:json][timeout:60];
node["shop"="convenience"](35.68,139.73,35.82,139.88);
out body;
```

## 手順

### Step 1: 事件データの絞り込み（実施済み・確認のみ）

絞り込みは完了している。想定される件数は以下。読み込み後に一致するか確認すること。

- 全体 21,253件 → 不審者・声かけ 2,677件 → うち丁目レベル **2,308件**
- 学習対象（23区から荒川を除いた22区）: **約1,599件**
- 検証対象（荒川区）: **72件**

丁目レベルの行だけを使う。電話詐欺・特殊詐欺は除外済み。

### Step 2: 住所の正規化 ← ここが最大の難所

事件データの住所と e-Stat の町丁目名は、そのままでは一致しない。

- 漢数字 ↔ アラビア数字（`荒川三丁目` / `荒川3丁目`）
- `丁目` の有無
- 全角 ↔ 半角
- 前後の空白

正規化関数を書いて両側に適用する。

**結合できた件数と結合率を必ず表示すること。**
結合率が 80% を下回る場合は、一致しなかった住所のサンプルを20件表示して原因を報告すること。
（ここを黙って進めると「データが無い」と誤診するため）

### Step 3: 特徴量の作成

町丁目ポリゴンに対して、施設の点データを空間結合して数える。

| 特徴量 | 作り方 |
|---|---|
| `koban_n` | 町丁目内 + **境界から300m以内** の交番数 |
| `school_n` | 同上 |
| `conveni_n` | 同上 |
| `pop` | e-Stat の人口総数 |
| `area_km2` | ポリゴン面積 |

**境界から300m以内も含める理由**: 隣の町丁目にある交番も駆け込み先として機能するため。
町丁目内だけで数えると、小さい区画がすべて0になって式が壊れる。

距離計算は平面直角座標系（EPSG:6677、東京都の系）に変換してから行うこと。緯度経度のまま距離を測らないこと。

人口0の町丁目（工業地帯・公園など）は除外する。

### Step 4: ポアソン回帰

```python
import statsmodels.api as sm

# 件数 ~ Poisson
# log(λ) = log(pop) + β1*koban_n + β2*school_n + β3*conveni_n + 区ダミー
```

- **人口を offset（`log(pop)`）に入れる** → 「人あたり発生率」が自動的にモデル化され、分母問題が解決する
- **区をダミー変数に入れる** → 所轄ごとの報告バイアスをここに吸収させる
- 予測時は **区ダミーを使わず、環境係数だけ** を使う。これでバイアスを除いた環境由来の危険度が出る

**学習と検証を分ける:**
- 学習: **23区のうち荒川区を除く22区**（約1,599件・町丁目約3,000）
- 検証: **荒川区**（72件・町丁目約52）
- **多摩地域は除外する**（丁目レベル比率が低く、町丁目の構造も23区と異なるため）

#### 区ダミーが吸収する2種類のバイアス

このデータには報告バイアスが2層ある。**どちらも区ごとの倍率なので、区ダミーで同時に吸収できる。**

1. **件数のバイアス**: 人口あたり件数が自治体間で最大9倍の差
2. **住所の詳しさのバイアス**: 丁目まで記載される率が港区6.2%・武蔵村山3.2%に対し、葛飾45.4%・足立43%と7倍以上の差

予測時は区ダミーを使わないことで、両方のバイアスを除いた環境由来の危険度が得られる。

#### 検証の指標（3つとも出すこと）

荒川区は72件と少なくノイズが乗るため、Spearman単独では不安定。以下3つを併記する。

1. **Spearman順位相関**（予測値 vs 実件数）
2. **Top-N一致率**: 予測上位10町丁目のうち、実件数上位10に入っている数
3. **3分位の単調性**: 予測値で町丁目を3群に分け、群ごとの平均実件数を出す。
   低群 < 中群 < 高群 と単調増加すれば成功。
   **これが最も説明しやすいので、プレゼン用に必ず出すこと**
   （例:「危険と予測した地域は、実際に事件が3倍多かった」）

### Step 5: 出力

以下を出力すること。

1. **係数の表**（各特徴量の係数、標準誤差、p値）
2. **荒川区での検証結果**（Spearman相関、散布図）
3. **`real.js` に貼れる形の JSON**:
```json
{
  "model": "poisson",
  "trained_on": "23区（荒川区を除く22区）",
  "validated_on": "荒川区",
  "spearman": 0.00,
  "top10_overlap": 0,
  "tercile_mean_counts": [0.0, 0.0, 0.0],
  "coefficients": {
    "intercept": 0.0,
    "koban_n": 0.0,
    "school_n": 0.0,
    "conveni_n": 0.0
  },
  "score_range": { "min": 0.0, "max": 0.0 }
}
```
4. **盲点リスト**: 予測値が高いのに実件数が0の町丁目 上位10件
   （「危険なのに報告されていない場所」= アプリの提供価値そのもの。プレゼンで使う）

## 進め方

**Step ごとに実行して結果を報告すること。** まとめて全部書かないこと。

特に Step 2 の結合率は、次に進む前に必ず確認する。
結合率が低いまま Step 3 以降に進むと、すべての数字が無意味になる。

各 Step の終わりに、データの行数・欠損数・想定外の値を報告すること。
